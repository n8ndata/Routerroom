ROUTER PROBLEM REPORT PLATFORM

index.html = หน้าปกเลือกโหมด ไม่ต้องกรอกชื่อผู้ใช้/รหัสผ่าน
  - ปรับใหม่แบบเรียบ/ทัดสมัย: หน้าปกมีหน้าที่เดียวคือ "เลือกโหมดการทำงาน"
    ตัดกล่องข้อมูลตกแต่ง (hero, รายการฟีเจอร์, แถบรับประกัน) ออกทั้งหมด เหลือเฉพาะปุ่ม + ไอคอน 2 ปุ่ม
  - ปุ่มใหญ่แตะง่ายบนมือถือ: การ์ดสีทึบ (ไม่มีไล่สี/โปร่งแสง) + ไอคอนสีทึบ + ป้ายโหมด + ชื่อโหมด + คำอธิบายสั้น + ลูกศร
    โหมด 1 = การ์ดน้ำเงินทึบ #2563eb + ไอคอนเหลืองทอง #f59e0b (ไอคอนรายการเช็ค)
    โหมด 2 = การ์ดม่วงทึบ #7c3aed + ไอคอนเขียว #10b981 (ไอคอนประแมงเครื่องจักร)
    ไอคอนสองโหมดใช้สีต่างกันชัดเจน ไม่ซ้ำกัน
  - พื้นหลังเทาอ่อนทึบ ไม่มีไล่สีเจือจาง เพื่อให้การ์ดสีตัดกันชัด (ป๊อป) และอ่านง่าย
  - เลย์เอาต์ fluid: มือถือ/แท็บเล็ต/คอมพิวเตอร์ + สไตล์พิมพ์ (พิมพ์ขาวดำ) + focus ring ชัดเจน
  - ไอคอนเป็น inline SVG ทั้งหมด ไม่พึ่ง CDN จึงเปิดใช้งานได้แม้ไม่มีอินเทอร์เน็ต
  - ฟอร์น Prompt + Plus Jakarta Sans พร้อม fallback สำหรับระบบ
work/ = ระบบรายงานปัญหางานจากไฟล์เวอร์ชันล่าสุด พร้อมบังคับผู้รายงานและ Supervisor และรองรับแนบรูป/ถ่ายรูปตามระบบเดิม
  - ปุ่ม "หน้าหลัก" เหลือจุดเดียว (ปุ่มในแถบหัวเรื่อง สีทองแดง) และถอดป้ายเวอร์ชันออกแล้ว
  - ปุ่ม "หน้าหลัก" แสดงคำว่า "หน้าหลัก" คู่กับไอคอนเสมอทุกขนาดจอ (ไม่ซ่อนบนมือถือ)
  - เมนูแต่ละแท็บมีไอคอนสีสันเฉพาะตัว (แดชบอร์ด/ลงข้อมูล/รายการ/ปฏิทิน)
  - ใช้งานง่ายขึ้น: เพิ่มแถบเมนูล่างตรึงล่างจอสำหรับมือถือ/แท็บเล็ต (≤1023px)
    มีแท็บ แดชบอร์ด / ลงข้อมูล / รายการ (พร้อมจำนวน) / ปฏิทิน / หน้าหลัก และซ่อนแถบเมนูบนบนจอเล็ก
    แท็บซิงค์กับแถบบนและกับปุ่ม "บันทึกปัญหาใหม่" ในแถบหัวเรื่อง (แสดงเป็นไอคอน + บนมือถือ)
machine/ = ระบบรายงานเครื่องจักรแยกหน้าแดชบอร์ด, ลงข้อมูล, กราฟสรุป, รายการ; มีเวลาเริ่ม-จบคำนวณ downtime, รูปหลายรูป/กล้องมือถือ, ดู/แก้ไข/ลบ, CSV/JSON/พิมพ์
  - ปุ่มกดทุกปุ่มมีไอคอนสีสันแยกตามหน้าที่ (แดชบอร์ด ลงข้อมูล รายการ กราฟ หน้าหลัก ดู แก้ไข ลบ) พร้อมเรืองแสงตอน hover
  - ปุ่ม "หน้าหลัก" แสดงคำว่า "หน้าหลัก" คู่กับไอคอนเสมอทุกขนาดจอ (ไม่ซ่อนบนมือถือ)
  - แถบเมนูล่างตรึงล่างจอสำหรับมือถือ/แท็บเล็ต และแถบเมนูบนสำหรับจอใหญ่ ตามระบบเดิม
  - แถบเมนูล่างมี "หน้าหลัก" เพิ่ม (แตะกลับหน้าปกเลือกโหมดได้ใน 1 จุด) เหมือนโหมด 1

กฎเดียวทั้งระบบ: ปิดการขยายซูม (ห้ามซูมทุกหน้า) — index.html / work/ / machine/
  - ทุกหน้าใช้ viewport: initial-scale=1.0, minimum-scale=1.0, maximum-scale=1.0, user-scalable=no
  - CSS touch-action: pan-x pan-y ทั้งระบบ (รวมคอนเทนเนอร์ที่เลื่อนได้) กันพินช์-ซูมและดับเบิลทัป-ซูม แต่ยังเลื่อนหน้าได้ทั้งแนวตั้ง/แนวนอน
  - JS กันซูมแบบ iOS (gesture), Ctrl/⌘+ล้อเมาส์, Ctrl/⌘+เคีย์บอร์ด (+,-,0) และดับเบิลทัปบนพื้นที่ที่ไม่ใช่ปุ่ม (ปุ่มยังกดซ้ำได้ปกติ)
  - หน้าพิมพ์ของโหมด 2 (หน้าต่างใหม่) ใช้ meta + CSS ชุดเดียวกัน
  - Lightbox ดูรูปขนาดใหญ่ยังใช้ได้ เป็นการดูภาพ ไม่ใช่การซูมหน้า
  - ข้อควรทราบ: การล็อกซูมถูกบังคับใช้ทั้งระบบ เพื่อความสม่ำเสมอบนจอประจำตำแหน่งงาน แต่ผู้ใช้ที่ต้องการขยายเพื่ออ่านข้อความเล็กควรใช้คุณสีของเบราว์เซอร์แทน

Firebase: system-routerf2; machine node = machine_reports. ต้องเปิด Authentication > Sign-in method > Anonymous และตั้ง Realtime Database Rules ให้อ่าน/เขียนสำหรับ auth != null จึงซิงค์ข้ามเครื่องได้. ตรวจสอบนโยบายสิทธิ์ก่อนเผยแพร่ เพราะผู้ใช้ anonymous ที่ผ่าน auth อาจแก้ไข/ลบข้อมูลได้ตาม rules.

ข้อควรทราบ: โหมดรายงานงานใช้โครงสร้าง Firebase/Storage เดิมจาก app.js และการเข้าแบบ anonymous; ควรทดสอบใน Firebase project ก่อนใช้งานจริง. Static files ต้องอัปโหลดไป Firebase Hosting หรือ static hosting จึงจะออนไลน์; ZIP ไม่ได้เผยแพร่เว็บให้อัตโนมัติ.
